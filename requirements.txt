# orgtree backend dependencies.  Install:  pip install -r requirements.txt

# Floors, not pins. This is a small app on a fast-moving stack, so exact pins
# would age badly — and a `pip freeze` would be worse still: the usual install
# is a system-wide Python shared with other projects, so a freeze captures every
# unrelated package on the machine (193 of them on the dev box) and turns a
# fresh install into a dependency-resolution fight.

fastapi>=0.110
uvicorn>=0.27

# ⚠ NOT OPTIONAL, and nothing imports it — which is exactly how it went missing.
#
# Plain `uvicorn` ships no WebSocket implementation. Without one the server does
# not fail loudly: it answers a WebSocket upgrade with a plain "HTTP/1.1 200 OK"
# and the request falls through to the SPA catch-all, so the browser gets HTML
# where it expected a protocol switch, the socket never opens, and the client
# reconnect-loops forever. Every HTTP endpoint keeps working perfectly, so the
# app looks fine and merely feels slow — the UI falls back to its polling
# heartbeats and every action lags by up to one poll interval. A user hit this
# on a second machine (2026-08-03); it was invisible from the dev box, which
# happened to have `websockets` installed for unrelated reasons.
#
# Measured in a clean venv: with the old manifest, upgrade -> 200 OK; with this
# line, upgrade -> 101 Switching Protocols.
#
# (`uvicorn[standard]` would also pull this in, along with httptools, watchfiles
# and friends. This is the one piece actually needed, so it is named directly.)
websockets>=12

# Imported DIRECTLY by the backend, not merely inherited from fastapi. They do
# arrive as fastapi's own dependencies today, but a direct import deserves a
# direct declaration — otherwise a future fastapi that drops or renames one
# breaks us with no clue why.
pydantic>=2.6           # api.py — request/response models
starlette>=0.36         # api.py — ASGI types, Request, responses
typing_extensions>=4.8  # schema.py — TypedDict/NotRequired on Python 3.10

httpx>=0.27             # api.py — outbound calls (bridge, cloud, chatq)

# FR-28/D-167 — imgblock.py, decode-validating an attached image before it is
# inlined into an agent's turn.
#
# ⚠ NOT cosmetic, and not merely for reading dimensions. Without a real decode
# a truncated or mislabelled file is base64'd straight to the API, which
# rejects the whole request — so a broken attachment kills the TURN rather
# than just the image, with an error naming nothing the user can act on.
# Pillow is what makes "this file is not a decodable image" a thing we can say
# in the mail block instead of a thing the agent discovers by dying.
#
# Degrades safely if absent: imgblock routes an unimportable Pillow to the
# SAME announce path as an oversized image, so the feature loses inlining and
# keeps its promise that nothing vanishes silently.
Pillow>=10

# D-201 — warm-pool memory telemetry (warmpool.py, keeper pass): per-pass RSS
# of every warm process tree plus machine free RAM, journaled into warm.jsonl
# pool rows. The import is lazy and ImportError-tolerant BY DESIGN — the pool
# must keep running without it — so a venv missing psutil fails nothing: it
# journals rss_total_mb=0.0 / free_ram_mb=0.0 forever, a blind instrument
# shaped like a working one, on the very number (warm-fleet RAM ceiling vs.
# free memory) the D-201 memory scoping was taken to the user over.
#
# Not hypothetical: the deployed venv lacked psutil on activation day
# (2026-08-30) and journaled zeros for ~3.5 hours while every dev box
# happened to have it — the websockets story above, replayed on a journal
# field instead of a protocol upgrade. In warm.jsonl, pool rows with
# rss_total_mb == 0.0 AND free_ram_mb == 0.0 from before this line reached
# the deploy mean "unmeasured", not "zero".
# backend/tests/test_warmpool_deps.py makes the absence loud.
psutil>=7
